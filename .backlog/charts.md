# Backlog: charts (Explore → Charts)

Findings from documenting the Charts page, the editor and the 19 chart types. Recorded, not fixed.
Severity: S1 blocks a task, S2 wrong or misleading with a workaround, S3 polish.

| Area | Type | Sev | Description | Evidence (page/URL/steps) |
|---|---|---|---|---|
| Charts / Object detail | Bug | S2 | The **Export chart** popover offers `.png` for Object detail, and the downloaded file is a 286-byte image of the pager arrow icon instead of the record (the exporter grabs the first `<svg>` in the preview). | Open chart "Order record" → download icon → **.png** → **Download**; the file is 286 bytes. |
| Charts / Progress | Bug | S2 | An empty **Goal** is treated as `0`, not as "no goal": the bar reads **Goal 0** and **Goal exceeded**. The message **No goal set** can never appear for an empty goal. | New Progress chart, **Metric** = Orders, no **Goal**. |
| Charts / Row | Misleading UI | S2 | The gallery says rows are "sorted by value", but a row chart is alphabetical until a **Sort** is added. With **Sort** = revenue descending, the largest bar is drawn at the bottom, so a "top 10" reads upside down; ascending order flips the ranking but then **Row limit** returns the smallest ten. | "Top clerks by revenue" (Sort revenue desc, Row limit 10). |
| Charts / Map | UX | S2 | A region value that matches no region is dropped silently. There is no note (pin maps do have one), and the legend range still includes the dropped rows' values. Easy to hit with Vietnam, whose keys are names such as `TP. Hồ Chí Minh`. | Map "Revenue by province" with a row named `Thành phố Hồ Chí Minh`: Ho Chi Minh City is unshaded, legend still tops out at its value. |
| Charts / Editor | Bug | S2 | **Change** (chart type) clears the X-axis, Y-axis and all other fields, even between bar, line, area and combo which share one settings namespace. Source comments say a bar → line switch keeps its config. | Open "Revenue by order priority" → **Change** → **Line**: **X-axis** shows **Pick a dimension…**, **Y-axis** empty. Same for bar → pie. |
| Charts / Box plot | Gap | S2 | Quartiles are computed in the browser from the raw rows the query returns, capped by **Row limit** (max 10,000). On a bigger dataset the box plot summarises only the first rows the database returns, with no warning. | "Line price spread by ship mode": Order lines has about 60,000 rows, the chart uses 5,000. |
| Charts / Editor | Misleading UI | S3 | The export popover says **The maximum download size is 1 million rows.** A chart fetches at most 10,000 rows, so the limit that applies is 10,000. | Editor → download icon. |
| Charts / Editor | UX | S3 | Axis titles, tooltip series names, the **Sort** field menu and the drill menu show database names (`revenue`, `orderpriority`), not the dataset's display names (**Revenue**), unlike the field pickers. | Bar chart "Revenue by order priority": tooltip reads `revenue: 434,187,711.87`; **Sort** menu lists `orderpriority`, `revenue`. |
| Charts / Editor | UX | S3 | **Row limit** is shown on Big number, Progress and Gauge, but the query always returns one row, so the box has no effect. | New Big number → **Data**. |
| Charts / Editor | Gap | S3 | There is no filter builder. Filters exist only as chips created by drilling into a value, so a chart cannot be restricted to a fixed condition without a custom dataset. | **Charts** page and editor; `FilterChips` is fed only by the drill menu. |
| Charts / Editor | Inconsistency | S3 | Spelling: **Colour** (Progress), **Conditional colours** (Big number), **Switch positive / negative colours** (Trend) against **color** on every other panel. | Display tab of those three types. |
| Charts / Editor | UX | S3 | Waterfall and box plot axes panels say **Show label** where the other types say **X label** / **Y label**, and have **Scale** instead of **Y scale**. | Axes tab of "Profit bridge" vs "Revenue by order priority". |
| Charts / List | UX | S3 | The Trash view's summary reads "1 chart · 1 folder" although folders are not shown in the Trash. | Move a chart to Trash while a folder exists → Trash view. |
| Charts / Funnel | UX | S3 | The **Steps** list only appears after the first run, and stage order follows the database order unless a **Sort** or the Steps list is used; nothing in the empty state says so. | "Checkout conversion" with the **Sort** removed. |
| Charts / Waterfall | UX | S3 | The **Total color** swatch shows slate (`#4C5773`) while the total bar is drawn in the dark text color by default, so the swatch does not match the bar until a color is chosen. | "Profit bridge" → **Display** → **Total color** vs the **Total** bar. |
| Charts / Formatting | UX | S3 | Identifier columns (`orderkey`, `custkey`) are formatted as numbers with thousands separators by default (29,989) in tables and Object detail. | "Order record" preview. |
