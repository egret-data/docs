# Known issues and roadmap

A running list, collected while writing these docs against a running instance, of defects, rough UX
and missing pieces. Entries are **recorded, not fixed**; they feed the product roadmap.

*Severity:* **S1** blocks a task · **S2** wrong or misleading, has a workaround · **S3** polish.
*Status:* **open** unless stated. **verify** means observed once and not yet reproduced.

| ID | Area | Type | Sev | Description |

| KI-001 | Databases | UX | S2 | Registering a dataset against a Trino without `http-server.process-forwarded=true` fails with a generic *502 Bad Gateway*. Egret always sends `X-Forwarded-Proto` and Trino answers HTTP 406. The UI should say what is wrong. *Status:* fixed in platform #748 (October 2026): **Test**, SQL Lab and dataset creation say *Trino refused the X-Forwarded-Proto header egret sends over plain HTTP (HTTP 406). Set http-server.process-forwarded=true in the coordinator's config.properties, or connect over https.* The connections page shows the failed test's detail (it said only *Failed* before), wrapped beside the row's buttons. |
| KI-002 | Auth | UX | S3 | Local sign-in is limited to 5 attempts per 5 minutes and rejected (429) attempts keep the window open. There is no message telling the user when they can retry. *Status:* fixed in platform #727 (October 2026): a refused sign-in answers 429 with `Retry-After` and `{"code":"rate_limited","retry_after_secs":…}`, and the page says *Too many failed sign-in attempts. Try again in 5 minutes.* Refused attempts do not extend the lockout. |

## Not verified

- **Kubernetes-only features:** StarRocks and RisingWave engines, ingress, autoscaling, pod logs and exec on engines, the Kubernetes kernel and app launchers. - **Ranger enforcement on an external engine:** the demo Trino has no Ranger plugin. Rule overlaps that already exist cannot be shown, because Egret refuses to create them.
- **Governed connections:** `data_access_denied` and `governance_stale` responses, and different rows per viewer in an app (`trino-demo` runs every query as `egret`).
- **Non-admin use:** a delegated (per-user) query by a non-admin through the UI, SQL Lab and dataset behaviour for a viewer, and the permissions needed for Tags. These were blocked by KI-159, which #712 fixed; they have not been re-checked for these docs.
