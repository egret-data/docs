# Known issues and roadmap

A running list, collected while writing these docs against a running instance, of defects, rough UX
and missing pieces. Entries are **recorded, not fixed**; they feed the product roadmap.

*Severity:* **S1** blocks a task · **S2** wrong or misleading, has a workaround · **S3** polish.
*Status:* **open** unless stated. **verify** means observed once and not yet reproduced.

| ID | Area | Type | Sev | Description |
|---|---|---|---|---|
| KI-001 | Databases | UX | S2 | Registering a dataset against a Trino without `http-server.process-forwarded=true` fails with a generic *502 Bad Gateway*. Egret always sends `X-Forwarded-Proto` and Trino answers HTTP 406. The UI should say what is wrong. |
| KI-002 | Auth | UX | S3 | Local sign-in is limited to 5 attempts per 5 minutes and rejected (429) attempts keep the window open. There is no message telling the user when they can retry. |
| KI-003 | Dashboards | UX | S2 | A chart that is not fully configured (no X-axis) renders as an **empty card** on a dashboard, with no hint, while the chart editor says *Set up your Bar*. |

## Not verified

The Docker demo stack (`just demo-up`) now exercises what the earlier demo instance could not: **Add engine** with the Docker provisioner (Trino), the Data Apps editor and viewer, PNG and PDF reports through the renderer, and SMTP delivery to Mailpit. These are still not exercised there, so the matching pages describe them from source and say so:

- **Kubernetes-only features:** StarRocks and RisingWave engines, ingress, autoscaling, pod logs and exec on engines, the Kubernetes kernel and app launchers.
- **Ranger enforcement on an external engine:** the demo Trino has no Ranger plugin. Rule overlaps that already exist cannot be shown, because Egret refuses to create them.
- **Governed connections:** `data_access_denied` and `governance_stale` responses, and different rows per viewer in an app (`trino-demo` runs every query as `egret`).
- **Non-admin use:** a delegated (per-user) query by a non-admin through the UI, SQL Lab and dataset behaviour for a viewer, and the permissions needed for Tags (blocked by KI-159).
- **Delivery:** Slack (no Slack app on the stack) and webhook request bodies (private and Docker hosts are blocked, KI-035; payload shape comes from source).
- **Workflows:** script tasks and `WorkingDirectory`, Kestra JDBC plugin tasks (no container runner or plugin host, refused with `task_type_not_served`), `egret.sql`, `egret.dataapi.call`, `egret.dataset.refresh`, `egret.report.send`, `core.http` and `core.slack` (no handler on any deployment), mail from a workflow (`MailSend` is unknown) and webhook calls (off on the stack, see KI-188).
- **SQL Lab errors:** `connect:`, `timeout` and authentication errors (the only connection is healthy and not delegated).
- **Demo stack lifecycle:** `just demo-up` from an empty machine and its build time, `demo-reset` and `demo-seed`, and the demo-stack upgrade path. Engine state after `demo-down`/`demo-up` is KI-213.
- **Elsewhere:** tagging BI objects, and "Limit this filter's choices" on dashboards.
- **UI consistency sweep (KI-214 to KI-235):** 78 admin screens in the light theme at 1440×900, the same 52 pages in the dark theme and at 768 and 390 px wide, the editors (SQL Lab with results, dashboard edit and filter settings, chart editor, flow editor, endpoint tabs, app editor) and a non-admin SSO member (`member-sso`, workspace *data-science-lab*). **Dark theme:** no defect found; a script found no light-coloured block on any of the 52 pages and 12 of them were checked by eye, and the native selects (KI-217) follow the dark palette.
